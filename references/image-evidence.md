# Image evidence contract (v1)

The shared scripts/image_evidence.py module is packaged in both skills and must remain byte-identical. It is a local serializer/verifier, not an audit engine or uploader. It uses the standard library, keeps bounded ZIP buffers and reads each JSONL member sequentially. Existing extraction still loads native findings in memory; this change does not claim fully streaming crawl analysis.

Defaults: row_limit=50000 (strictly greater triggers), preview_rows=1000, target_bytes=8388608. Configure output.image_delivery in the producer runtime JSON; settings are recorded in the manifest. Preview rows must be positive and at most 1000. The target applies to individual image XLSX/ZIP delivery files, not an inferred server cap or a guarantee for unrelated module files. If even a compact workbook or one evidence row cannot fit the selected target, fail explicitly and retain source evidence; do not silently drop content.

The producer keeps the four existing XLSX filenames. Compact image reports carry [COMPACT_IMAGE_EVIDENCE_V1] in affected Checklist Findings and an adjacent <image-workbook-stem>.evidence.json manifest. Original Findings precede the presentation note. Displayed detail rows retain original order and existing columns. Findings count total references, displayed references, distinct nonempty Destination values and distinct nonempty Source values separately. A repeated reference remains a repeated evidence row.

The manifest schema is image-evidence-v1. It records run_id, site_name, site_url, audit_date, effective settings, source provenance, source workbook filename/SHA-256 and a checks object keyed by compact check ID. Each check records original headers, reference_rows, unique_assets, affected_pages, displayed_rows, preview, original_finding, exact displayed checklist, switching reason and parts. A part records a basename, ZIP member, compressed/uncompressed sizes, SHA-256, first_row, last_row and row_count. JSONL lines contain row (1-based ordinal) and values (original ordered values). Each ZIP is independently readable; no extraction or concatenation is required for verification. Preserve full findings.json/raw native evidence for additional fields not present in the legacy image detail schema; the manifest carries original export hashes/provenance. Do not imply that missing alt/context fields have been reconstructed.

Verify every ZIP hash, safe relative path, member, bounded expanded size, continuous row range, total count, distinct asset/page count and preview equality. URL host validation applies to all evidence rows during consolidation, not only the preview. Spreadsheet text remains literal. A modified/missing package or disagreement with the selected workbook blocks output. Recheck dependencies before publication and standalone verification.

## Producer usage

Use the existing onsite_checklist.py command. Set the shared config run_id explicitly for multi-module jobs. Otherwise the resolved run directory supplies a local run identity, which the consolidator must explicitly reuse. Do not change the audit's fixed title/description/image thresholds. Large images do not cause the other three reports to be omitted.

The renderer checks row count before rendering image details; if the rendered image XLSX exceeds target_bytes, it rebuilds confirmed image checks as previews and packages complete detail rows. No new crawl/export is performed. Old small reports remain unchanged in layout.

For delivery select all four workbooks plus required validation artifacts and every run-status.json.image_evidence entry. For an authorized downstream consolidation, supply the image XLSX AND its manifest/packages in the selected run and set source.image_evidence explicitly. Never send just the preview workbook as complete evidence. Hand over exact reachable attachments and checksums once; do not tell the human to reconstruct byte fragments. Attachment and archival state are separate from local run-status complete.

For compact delivery, full findings.json and raw exports remain preserved local evidence; do not automatically attach another oversized duplicate of the JSON rows. Deliver the validated image manifest/packages, reports and run-status/manifest metadata. If full findings.json is separately requested as a final deliverable, package and verify it explicitly rather than silently omitting it.
